# UI 场景提示词生成技能

主要交付是可复制的提示词包。根据用户需求生成新提示词，或优化用户已有提示词；生成图片和页面属于后续明确请求的工作。

## 输入

先从用户资料提取产品用途、场景数量、目标尺寸、参考素材、需要保留的风格和页面内容。缺少信息时，列出可修改的假设并继续。已有参考图先查看，已有项目先定位素材及使用位置。

## 工作流

1. 写一句读者或用户要完成的任务，例如选择校园身份后进入故事。列出对应的页面、插画和操作区域。
2. 固定视觉约束。记录人物年龄、发型、服装、建筑年代、镜头高度、画法、配色与文字区域。参考图有矛盾时说明取舍。
3. 建场景矩阵。每项写场景名、剧情用途、主体动作、景别、光线、辅助道具、横竖用途和文字留白位置。通过镜头与动作制造变化。
4. 输出母提示词及每场景的可复制完整提示词。完整提示词应带上必要固定设定，单独复制后仍能理解。保留可替换变量，注明哪些是固定项。
5. 用户需要 UI 页面时，另给页面实现提示词。说明技术栈、图片输入、布局、状态、交互和屏幕适配。用无字插画做背景，标题与按钮由页面排版。
6. 给迭代指令。每轮针对一个观察到的问题修改，记录原提示词、修改句和生成结果。未执行生成时，把调整建议标为待试用。
7. 检查素材包。检查角色与道具连续性、手与物件的关系、文字区、目标屏幕裁切、亮暗背景可读性及加载失败状态。

## 交付

默认用 Markdown 交付以下内容，用户指定其他形式时遵循其要求。

- 需求与假设，视觉固定项及可变项。
- 场景矩阵、母提示词、逐场景完整提示词。
- 页面实现提示词，明确素材与交互的连接方式。
- 一张问题与修改指令对照表。
- 验收清单，以及素材、提示词和实测结果的来源状态。

原有图片、新整理提示词和新生成结果分别注明来源。只有实际执行后才记录效果和耗时。写提示词的任务不自动扩展为生成图片、修改项目或发布。

## 文章与推广

当用户要求把结果写成分享文章时，遵循所在仓库的写作规范。开头介绍作者、问题和读者能拿走的内容，用具体场景展示技能如何工作。输出一段可直接复制的调用示例。

humeng 承接提示词，网站承接界面案例。是否已收录以用户确认或实际操作为依据。技能源码公开地址、二维码和菜单路径取得证据后再写入。

## 主题包

校园、青春与毕业纪念任务读取 [校园风生成规则](references/high-school-campus.md)，再按需读取 [五场景提示词包](../../themes/high-school-campus/README.md)。将主题约束与用户变量合并，生成逐条完整提示词；新场景延续同一固定表。主题包保留实例，参考文件指导如何创作新提示词。
